# Chapter 13: Cognitive Planning & Action Sequencing

This chapter establishes the Large Language Model (LLM) as the central Cognitive Planner that bridges the gap between the human's abstract intent and the robot's discrete, executable actions.

## 13.1 LLM as the Task Decomposer
In traditional robotics, complex tasks were broken down manually by an engineer (e.g., using Planning Domain Definition Language - PDDL). The LLM replaces this process by using its vast knowledge base and reasoning capabilities to automatically decompose a natural language command into a series of atomic actions.

*   **Atomic Action Library**: The robot system maintains a predefined list of high-level, executable ROS 2 Actions and Services that the robot knows how to perform. The LLM's task is strictly to sequence calls to this library.
    *   **Examples**: `Maps_TO(location)`, `PICKUP_OBJECT(object_id)`, `DETECT_OBJECT(label)`, `MOVE_ARM_TO(pose)`.
*   **Contextual Reasoning**: The LLM's planning is grounded by feeding it the robot's current state (e.g., "Robot is at Kitchen entrance," "Red cup is on the counter") alongside the user command. This allows the LLM to generate plans that are physically possible and contextually relevant.

## 13.2 Prompt Engineering for Structured Output
To ensure the LLM's plan is executable, the output must be structured (not free-form text) and contain specific parameters. This is achieved through careful Prompt Engineering.

The LLM is given a detailed system prompt that defines its role and constraints:
*   **Role**: "You are a robotic task planning agent. Your sole purpose is to convert a user's instruction into a JSON-formatted sequence of atomic actions."
*   **Available Actions**: The full list of atomic actions and their required parameters is provided (e.g., `Maps_TO` requires a `target_name: string`).
*   **Output Format**: The prompt explicitly forces the output into a verifiable structure, typically JSON or YAML, which the robot's executive agent can easily parse.

## 13.3 Natural Language to Structured Action Translation
The robot's executive agent receives the transcribed text (from Whisper) and the current environment state (from Isaac ROS perception) and sends it to the LLM. The LLM returns a structured plan.

## 13.4 Execution and Reflection
Once the JSON plan is received, the robot's executive agent (a ROS 2 node) iterates through the list. For each step:
*   It validates the action and parameters.
*   It sends the corresponding ROS 2 Action Goal (e.g., a Nav2 goal for `Maps_TO`).
*   It monitors the action for success or failure.
*   If an action fails (e.g., `PICKUP_OBJECT` fails because the mug is knocked over), the executive agent feeds the failure context back to the LLM for re-planning ("I failed to pick up the mug at KitchenCounter. Propose a new plan.") This creates the crucial closed-loop reasoning necessary for real-world robustness.
